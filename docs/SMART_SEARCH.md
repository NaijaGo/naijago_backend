# Catalog-backed smart search

Catalog attributes are always searched first. An optional bounded Gemini fallback
interprets a zero-result query and searches the same catalog again. AI previews
and product-request workflows remain separate unchecked release items.

## Contract

`GET /api/products/search?format=discovery&q=women%20clothes`

Returns `products`, `intent`, `collection` (title and type chips), `total`, `page`,
`limit`, `hasMore`, `interpretation` (catalog_attributes or gemini_intent).
Existing consumers of `/search` without this format still get
an array. The general `/products` listing endpoint is unchanged.

Combined parameters: category, subcategory, brand, vendor ID, gender, ageGroup,
productType, minPrice, maxPrice, minRating, inStock, sort, page, limit, ai. Use
productType=all to broaden types without dropping audience or other filters;
ai=false opts out of AI interpretation. Page size is
bounded to 100; customer pages use 30. Query and numeric inputs are validated;
user regex metacharacters are escaped. Store names resolve only approved vendors.

`GET /api/products/search/attributes` exposes the shared versioned vocabulary.
Unknown model and brand words remain literal terms. Gender boundaries prevent
`men` matching inside `women`; children are classified separately from adults.
No stock, price, listing, rating or sales figures are generated by this search.

## Optional Gemini interpretation (disabled by default)

Backend variables only; never put a Gemini secret in Dart defines:

- SMART_SEARCH_AI_ENABLED=true
- GEMINI_API_KEY: reuse the existing backend key.
- GEMINI_SEARCH_MODEL: optional explicit text model; otherwise GEMINI_CATALOG_MODEL.
- GEMINI_SEARCH_DAILY_LIMIT: required positive request budget (no budget means no AI calls), capped at 10000.
- GEMINI_SEARCH_USER_DAILY_LIMIT: per hashed network identity, default 20, maximum 100.

Requests use strict enum JSON schema, confidence >= 0.85, a six-second provider
timeout and no automatic provider retries. No-match/invalid/provider-failed
interpretations fall back to the original database result. Model/capacity tokens
containing digits must survive interpretation. Explicit filters and already-known
audience/type constraints cannot be replaced by AI. This is classification, not
embedding-based semantic similarity or invented inventory.

Mongo cache keys and quota identities are HMAC hashes, not raw query/IP identifiers.
Successful classifications cache for 24 hours; negative results for five minutes;
errors/quota failures briefly cool down. Atomic leases avoid simultaneous paid
calls for one query. UTC daily quotas are global across instances; failed provider
calls still consume quota conservatively. Cached results do not spend quota.
Changing the model or search-schema version changes the cache identity.

Search requests are limited to 60/minute per network using the existing proxy
configuration. This HTTP limiter is per server process; global AI spending limits
are Mongo-backed. Verify trusted proxy topology before production; forwarded IP
headers must not be accepted from arbitrary direct clients. Provider billing
alerts remain necessary: request counts are not an exact monetary budget.

The customer labels Smart matches and offers Original words / a filter switch.
Only actual database products can be returned. Query text is sent to Gemini only
on this enabled fallback; update the privacy notice before enabling it.

## Data

Optional editable product fields: gender, ageGroup, productType, plus existing
brand and searchTags. Category/subcategory are preserved. Product validation
derives searchAttributes (version, categoryPath, family, audience, types, tokens).
Both vendor and admin forms edit these fields. Explicit attributes take priority
over inference. Verify inferred attributes; do not assume legacy titles are clean.

Search uses approved active products. Primary offers provide the actual price,
discount and stock used in filtering; database sorting uses the same effective
price. Count and pagination are computed on the server, not a capped first page.
Existing payment/cart stock validation remains authoritative at order time.

Discovery also requires an approved vendor owner (or a vendor-free NaijaGo
product) and an eligible approved offer seller. A product with only disabled or
ineligible offers cannot fall back to stale product-level prices/stock. Legacy
products with no offers retain the product-level fallback. Search presents the
one selected offer snapshot used by the aggregate, not a second offer query that
could change the displayed budget/stock after filtering. Checkout must still
revalidate current price and stock. This does not alter the legacy listing/search
API or replace their separate seller/availability regression audit.

## Backfill - not yet run against production

1. Take a fresh database backup and rehearse on an isolated restored database.
2. `node scripts/migrateSearchAttributes.js` (dry run).
3. Review ambiguous audience counts and representative categories.
4. `node scripts/migrateSearchAttributes.js --apply` only after approval.
5. Repeat dry run; changed count should be zero. Recheck concurrent-edit conflicts.

The migration writes only derived metadata, preserves timestamps and checks
updatedAt to avoid overwriting concurrent edits. Roll back this derived field
from the backup if necessary; never delete or rebuild products/orders.
Application save hooks derive attributes for new/edited products. Direct bulk
database writes must also run derivation/backfill. Legacy metadata-free documents
have a bounded regex fallback until migration; performance testing on real data
and index review are still required before release.

## Required release checks

Prepared database gate: from the backend run
`powershell -NoProfile -ExecutionPolicy Bypass -File .\scripts\runAtlasIntegrationTests.ps1 -RunTests -Suite Search`.
It exercises the real aggregation and concurrent cache/quota writes with synthetic
fixtures, injected per-run collection names and simulated AI responses only.
Authenticated Atlas Search execution is pending; see ISOLATED_DATABASE_TESTS.md.

- Run aggregate queries against an isolated MongoDB copy (unit tests do not replace this).
- Audit category/audience/type inference, especially generic bags, shoes and unisex goods.
- Verify vendor store search, NaijaGo and vendor offers, discounts, stock and all combined filters.
- Customer: collection chips, View all, page two, stale-response handling and poor-network retry.
- Measure query plans/latency at expected catalog size and verify proxy/rate-limit behavior.
- Verify the configured Gemini model and structured output in a controlled provider test.
- Complete the explicitly non-purchasable preview/request flow.

Provider contract: https://ai.google.dev/api/generate-content (checked 2026-09-20).
The current API uses responseFormat.text.mimeType=APPLICATION_JSON, not the
lowercase MIME string that previously caused the catalog builder to fail.
