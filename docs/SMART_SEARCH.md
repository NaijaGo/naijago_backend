# Catalog-backed smart search

The current implementation is the deterministic foundation. Gemini interpretation,
AI previews and product-request workflows remain separate unchecked release items.

## Contract

`GET /api/products/search?format=discovery&q=women%20clothes`

Returns `products`, `intent`, `collection` (title and type chips), `total`, `page`,
`limit`, `hasMore`. Existing consumers of `/search` without this format still get
an array. The general `/products` listing endpoint is unchanged.

Combined parameters: category, subcategory, brand, vendor ID, gender, ageGroup,
productType, minPrice, maxPrice, minRating, inStock, sort, page, limit. Page size is
bounded to 100; customer pages use 30. Query and numeric inputs are validated;
user regex metacharacters are escaped. Store names resolve only approved vendors.

`GET /api/products/search/attributes` exposes the shared versioned vocabulary.
Unknown model and brand words remain literal terms. Gender boundaries prevent
`men` matching inside `women`; children are classified separately from adults.
No stock, price, listing, rating or sales figures are generated by this search.

## Data

Optional editable product fields: gender, ageGroup, productType, plus existing
brand and searchTags. Category/subcategory are preserved. Product validation
derives searchAttributes (version, categoryPath, family, audience, types, tokens).
Both vendor and admin forms edit these fields. Explicit attributes take priority
over inference. Verify inferred attributes; do not assume legacy titles are clean.

Search uses approved active products. Primary offers provide the actual price,
discount and stock used in filtering; database sorting uses the same effective
price. Count and pagination are computed on the server, not a capped first page.
Existing payment/cart stock validation remains authoritative at order time.

## Backfill - not yet run against production

1. Take a fresh database backup and rehearse on an isolated restored database.
2. `node scripts/migrateSearchAttributes.js` (dry run).
3. Review ambiguous audience counts and representative categories.
4. `node scripts/migrateSearchAttributes.js --apply` only after approval.
5. Repeat dry run; changed count should be zero. Recheck concurrent-edit conflicts.

The migration writes only derived metadata, preserves timestamps and checks
updatedAt to avoid overwriting concurrent edits. Roll back this derived field
from the backup if necessary; never delete or rebuild products/orders.
Application save hooks derive attributes for new/edited products. Direct bulk
database writes must also run derivation/backfill. Legacy metadata-free documents
have a bounded regex fallback until migration; performance testing on real data
and index review are still required before release.
